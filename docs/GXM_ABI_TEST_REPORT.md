## 1. Purpose and scope

The generated layer maps all 100 imported SceGxm stubs (`0x812B11C0`..`0x812B17F0`,
matching `_gxm_table.csv`) to guest-ABI decoders:

```
uint32_t gxm_abi_call_<NID>(uint32_t* regs, uint32_t* stack_args);
const gxm_abi_entry g_gxm_abi_table[100];
const gxm_abi_entry* gxm_abi_lookup(uint32_t stub_va);
uint32_t gxm_abi_dispatch(uint32_t stub_va, uint32_t* regs, uint32_t* stack_args);
```

This test validates the **ABI layer only**: dispatch/lookup, register and stack argument
decoding, the three manual argument remaps, guest-VA pointer translation, RAW pointer
pass-through, out-handle round-trips, unmapped-stub behaviour and return-code
passthrough. It does not boot the harness, does not touch the generator, and contains no
game data.

## 2. How the backend is isolated

`gxm_abi.cpp` declares the runtime backend functions `extern "C"` but does not define
them. The test links the generated `.cpp` together with strong **recording test doubles**
for all 26 backend functions that the 100 wrappers can call (the typed `kind == 0`
wrappers plus `sceGxmTerminate`, the single `kind == 2` placeholder with a real body).
Each double records every decoded argument; the int-returning doubles return a
test-controlled 32-bit value, and four create-style doubles write a test-controlled host
handle through their out-parameter.

The three translation hooks are also strong definitions in the test, exactly as the real
harness provides them, overriding the weak defaults shipped in `gxm_abi.cpp`:

* `p5d_abi_translate64(guest_va)` - maps the fake guest window `[0x80000000, +0x1000)`
  into a process-local arena; records call count / last VA.
* `p5d_abi_translate(guest_va)` - 32-bit fallback hook; claims one sentinel VA
  (`0x8FFFFFFF`) to prove the fallback path is reached.
* `p5d_abi_untranslate(host_ptr)` - maps arena pointers and four fake host handles back
  to guest VAs (`0x80100000 + i*0x10`); untranslatable pointers map to 0.

No runtime `.o` file (`gxm_sce.o`, `gxm_vk.o`, `gxm_tex.o`, `mem_addrspace.o`,
`common_log.o`) and no Vulkan library are linked. This keeps the test deterministic and
headless; see section 6 for what that does not cover.

## 4. Measured facts about the generated layer

All of the following are asserted by the test against the actual generated table:

* 100/100 stubs mapped; table strictly sorted by stub VA; NIDs and stubs unique.
* Kind census: **25 typed** runtime calls, **74 STUB_LOG-only placeholders**,
  **1 placeholder with a real body** (`sceGxmTerminate`).
* Stack-argument census: **17 entries declare more than 4 guest arguments** (this matches
  the task brief's "17 stack-reading functions"), but only **6 typed wrappers actually
  read `stack_args`**: `sceGxmSetViewport` (3 words), `sceGxmBeginScene` (4),
  `sceGxmDraw` (1) and `sceGxmTextureInitLinear/Swizzled/Tiled` (2 each) - 14 stack words
  in total. The other 11 high-arity entries are placeholders that drop up to 20 guest
  arguments (`sceGxmTransferCopy` declares 20).
* The 3 manual argument remaps (`sceGxmBeginScene`, `sceGxmDraw`, `sceGxmSetViewport`)
  decode exactly as documented in `gxm_abi_gen.py`'s `MANUAL_ARG_MAP`.
* All 6 documented RAW pointer arguments are passed through untranslated, bit-exact:
  `sceGxmMapMemory`/`sceGxmMapFragmentUsseMemory`/`sceGxmMapVertexUsseMemory` `base`, and
  `sceGxmTextureInit{Linear,Swizzled,Tiled}` `data`.
* 4 out-handle writers (`SyncObjectCreate`, `CreateRenderTarget`, `CreateContext`,
  `ShaderPatcherCreate`) round-trip the backend host handle through
  `p5d_abi_untranslate`; the 2 Usse-memory mappers do the same for their `void*` return.
* Return values are passed through bit-exactly (0, positive, negative error codes, full
  32-bit patterns such as `0xDEADBEEF`, `0x80000000`, `0xFFFFFFFF`).

All seven were detected (every mutated build exited 1 and the expected case name
appeared as `[FAIL]`):

| Mutation | Detected by |
|---|---|
| M1: `sceGxmMapMemory` RAW base translated instead of passed through | `map_memory_raw`, `map_usse_memory` |
| M2: `sceGxmSetViewport` manual argument order replaced by positional order | `set_viewport` |
| M3: `sceGxmDraw` indexCount read from `stack_args[1]` (off-by-one) | `draw`, `null_inputs` |
| M4: unmapped `gxm_abi_dispatch` returns garbage instead of 0 | `lookup_unmapped` |
| M5: `sceGxmSyncObjectCreate` stores the raw host pointer instead of untranslating | `sync_object_create` |
| M6: `sceGxmTextureInitLinear` reads mipCount from `stack_args[0]` | `texture_init_linear`, `texture_init_swizzled`, `texture_init_tiled` |
| M7: `sceGxmBeginScene` swaps color/depth arguments | `begin_scene` |

## 6. Limitations / residual risks

No functional defect was found in the tested ABI-layer scope. The following are outside
this test and remain integration risks:

1. **Backend ABI compatibility is not link-checked.** The generated `.cpp` declares the
   backend functions with simplified `extern "C"` prototypes rather than including
   `src/gxm/sce_gxm.h`, so the compiler cannot detect a signature mismatch between the
   two translation units. The test doubles here are defined with the `sce_gxm.h`
   prototypes (all 26 compile and link cleanly against the generated call sites, and the
   argument/return ABI is identical), but a future full-link test against the real
   `gxm_sce.o` / `gxm_vk.o` / `gxm_tex.o` / `mem_addrspace.o` / `common_log.o` objects is
   still recommended. Note that `-DGXM_ABI_CALL_STUB_IMPLS=1` would be required to
   exercise the 74 placeholder bodies.
2. **Placeholder coverage is intentionally shallow.** 74 of 100 wrappers return 0 to
   guest code because the backend only has `(void)` STUB_LOG placeholders. The ABI layer
   is correct, but guest code that expects real values from getters (for example
   `sceGxmTextureGetWidth` is imported with 767 call sites,
   `sceGxmProgramFindParameterByName` with 116,329 in `_gxm_table.csv`) will observe 0.
   This is a backend-completion issue, not an ABI-layer bug.
3. **RAW pointer policy is backend-dependent.** The 6 RAW arguments are deliberately
   untranslated because the legacy backend stores the 32-bit VA in guest-visible
   structures. The test verifies exact pass-through; it cannot verify that the legacy
   backend's own mapping window matches the harness guest memory layout.
4. **32-bit fallback hook truncation.** `gxm_abi_xlate` falls back to
   `p5d_abi_translate` (uint32 -> uint64) when the 64-bit hook returns 0. On Win64 a heap
   pointer above 4 GiB would be truncated if the harness implemented only the 32-bit
   hook. The test covers the control flow; the real harness must implement
   `p5d_abi_translate64`.
5. **No live backend / lifetime / concurrency testing.** Vulkan is never initialized and
   there is no real GXM context, render target or sync object, so real handle lifetimes,
   threading and GPU-state effects are out of scope.
