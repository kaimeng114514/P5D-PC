# P5D 移植项目 · 操作易错点清单（Operation Checklist）

> 目的：防遗忘机制已能防"知识误判"，但**不能防"操作层面的重复错误"**。本清单针对重复发生的操作错误，
> 每轮开始前用 10 秒扫一遍。新增错误时追加到对应分组。

## A. 地址与常量（最高频错误）

- [ ] **所有 0x8115xxxx / 0x811Dxxxx 地址必须写满 8 位并核对"5"**：0x8115D1F0 ≠ 0x811D1F0。
      （已犯错 2 次：M403、M410）
- [ ] 引用函数地址前，先在 `grep -c "0xADDR" recomp_harness.cpp` 确认**出现次数**：
      `0x8120732Cu` 出现 **8 处**（781/873/890/947/1243/1314/1331/1470）——搜索会命中错误的那个！
      （已因 8 处同名地址浪费 2 轮：M418、M420）
- [ ] 定位一个块时**不要用 `if ((pc & ~1u) == 0xADDR)` 当锚点**，用**该块里的 printf 行号 - 4** 定位。
- [ ] 栈偏移以**块入口 sp 为基准**逐一算清：
      0x8115D29A: `add sp,#4` + 9 pops → pc 在 [entry_sp+0x24]
      0x8120732C: `str r5,[r4]` + `add sp,#0xC` + pop{r4,r5,pc} → pc 在 [entry_sp+0x14]
      **先算偏移再 dump，别猜范围**（已犯错 2 次：M406、M417）
- [ ] 监控一个地址范围时，先确认目标地址**落在范围内**：
      [sp+14]=0xA05FFF2C → 范围必须含 0xA05FFF2C（不是 A05FF000 起的 64 字节）。
      （已犯错 2 次：M427 两个范围都不含目标）

## B. harness 编辑（每次改两份副本）

- [ ] **每个 instrumentation 块都有两份副本**：fiber_exec (`s->r[]`) 与 run_guest (`s.r[]`)。
      **grep 副本数量再改**（已犯错 3 次：M416、M419、M420）
- [ ] run_guest 是 `RecState s`（值对象）→ 必须 `s.r[]`；fiber_exec 是 `RecState* s` → `s->r[]`。
- [ ] **绝不用 `open(w).write(list)`**：先构建并校验完整字符串，再写一次。
      （已造成事故：M408 kb_audit.py 被截断归零，恢复花了 1 轮）
- [ ] 插入代码块前，确认插入点**在 `pc`/`s` 作用域内**（dispatch 循环内），否则 `'pc' was not declared`。
      （已犯错 3 次：M418、M420、M420b）
- [ ] 全局变量命名前先 `grep "static .* g_<name>"`，避免 `redefinition`（已犯错 1 次：M420 g_slot_watch）

## C. 环 / 日志的正确性

- [ ] **所有"回放环"必须按执行上下文拆分**：fiber_exec 与 run_guest 各一个。
      `g_pc_ring` / `g_tr_pc` 是混合环 → 读它们的尾部会得到**错误的"最新块"**。
      （已犯错 2 次：M370 dispatch ring、M407 pc ring）
- [ ] 已拆分的纯环：`g_dfe_pc`（fiber_exec，20 项）、`g_drg_pc`（run_guest，20 项）、
      `g_mr_pc/g_mr_nx`（fiber_exec 块→返回 pc，40 项）。
- [ ] 打印限制不够会漏掉异常（`< 3` 只看到正常调用）——**定位异常时先放宽到 200000 再 grep**。
- [ ] 监控"栈顶 sp 处的值"太粗（push/pop 就会变）——**监控"固定地址槽"**。

## D. 调试策略

- [ ] **先打印真实数据，再改代码**。连续 2 轮"基于假设改代码"都失败（M414/M416）→ 已教训。
- [ ] 一次实验只改**一个变量**（范围/窗口/过滤条件），否则无法归因。
- [ ] 异常路径的判定标准要**先写下来**（如"pc 槽不在 [0x81000000,0x812B3000) 即异常"），
      再用同一标准筛数据，避免手写阈值反复出错。
- [ ] 已知正常形态先记录（如 19/22 条 D72C 正常：lr=0x8120732C + 有效 pc 槽），异常对比才有意义。

## E. 文档与守卫

- [ ] 每轮结束：doc §18.x（ANTI-FORGETTING ENTRY）+ kb_audit 锚点 + 三重守卫 + 备份。
- [ ] 锚点插入脚本**先校验、再单次写入**；doc 同样是"构建完整字符串再写一次"。
- [ ] 失败轮也要写文档（失败原因 + 回滚点 + 下一步），否则下轮会重蹈。

## G. 工具文件事故登记（2026-10-27）

- [ ] **写入 kb_audit.py 锚点字符串时，字符串内不得出现未转义的双引号**：
      M442 锚点里写了 `(chk % ("s->",)...)` -> kb_audit.py 语法错误（line 20），三重守卫全部失效但退出码仍显示 PASS。
      规则：写完锚点后立即 `python -c "import ast; ast.parse(open(...).read())"` 做语法校验，再跑 kb_audit。
      另一个选项：锚点文本中避免任何引号，用改写描述（如 s-arrow）代替。
- [ ] 任何对 kb_audit.py 的写入后必须校验：文件大小 > 90KB 且语法可解析。
